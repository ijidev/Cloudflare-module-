# Cloudflare WHMCS Module v2.2 Documentation
## The Infrastructure-Driven DNS Mastery

Welcome to the comprehensive guide for the **Cloudflare WHMCS Module**. This document details the inner workings of our "Infrastructure-First" philosophy and how to maximize the module's performance.

---

## 🏗 Infrastructure Management

### Clusters & IPs
The module revolves around **Infrastructure Clusters**. Each cluster represents a physical or virtual server environment (e.g., "Web Cluster 01").
- **Primary IP**: The main IP address assigned to the cluster.
- **Historical IPs**: When you update a cluster's IP, the module records the previous one. This allows the "Self-Healing" system to identify domains still pointing to old infrastructure and migrate them automatically.

### DNS Templates
Define a global blueprint for every domain on a cluster.
- **Dynamic Variables**: Use `{domain}` for the user's domain and `{ip}` for the cluster's current IP.
- **Automatic Sync**: Any domain mapped to the cluster will receive these records. If you update a template, you can "Force Sync" the entire cluster with one click.

## 🔄 The Self-Healing System (Logic Breakdown)

Our most powerful feature is the **Global Sync Hub**. Here is how the logic works under the hood:

1.  **Scanner**: The system iterates through all **Active** hosting services in WHMCS.
2.  **IP Matching**: For each domain, it checks the public A-record.
    - Matches **Current IP**? $\rightarrow$ Domain is healthy.
    - Matches **Historical IP**? $\rightarrow$ Domain is marked for **Migration**.
3.  **Auto-Linking**: If a domain matches an IP but isn't linked to a product in our module, the system automatically creates the link.
4.  **Template Enforcement**: The system compares Cloudflare's current records with your Cluster Templates. Missing records are added, and incorrect records (pointing to old IPs) are updated.
5.  **Logging**: Every single update is logged with "Old Value" vs "New Value" for full transparency.

## 👤 Client Experience

### The Domain Mapping Modal
If a client adds a domain to Cloudflare that isn't their primary WHMCS hosting domain (e.g., an addon domain), the module triggers a **Mapping Required** prompt.
- **Service Selection**: Clients select which of their active hosting plans the domain belongs to.
- **Type Selection**: Choose between "Primary" or "Addon".
- **Verification**: If enabled, the module performs a real-time WHM API query to verify the domain actually exists on that server.

### Real-Time DNS Management
Clients can manage their own records with enterprise features:
- **Custom TTL**: Support for "Auto" (1) up to 24 hours (86400).
- **Proxy Toggle**: Easily switch the Cloudflare orange cloud on/off.
- **Bulk Actions**: Purge all cache or pause Cloudflare in emergencies.

## ⚙️ Administrative Settings

- **Sync Without Product Mapping**: Enable this to bypass WHMCS product logic and sync purely based on IP matches. Ideal for migrated accounts.
- **Verify Addon Domains**: Connects to WHM to prevent clients from mapping domains they don't own.
- **IP Retention History**: Configure how many previous IPs the module should "remember" for migration purposes (Recommended: 3).
