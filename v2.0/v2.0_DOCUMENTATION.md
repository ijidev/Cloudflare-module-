## 1. Initial Setup & Activation

Before using the module, you must activate the addon and configure permissions:

1. **Activate the Addon**: Go to **Setup -> Addon Modules**. Find **Cloudflare Manager** and click **Activate**.
2. **Set Permissions**: Click **Configure** for the Cloudflare Manager addon. Check the **Full Administrator** (or relevant staff group) checkbox to grant access to the settings page.
3. **Access the Module**: You can now find the manager under **Addons -> Cloudflare Manager**.

## 2. Admin Configuration Guide

Access the manager via **Addons -> Cloudflare Manager**.

### A. Global Configuration
- **Master API Token**: Enter your Cloudflare Global API Token or a Scoped Token with  for `Zone:Edit`, `Account:Edit`, and `DNS:Edit`.
- **Master Account ID**: Found in your Cloudflare dashboard URL (the alphanumeric string after `/dash/`).
- **Pro Addon ID**: The ID of the WHMCS Product OR Addon that unlocks "Pro" features.
    - **How it works**: The module scans the client's account for an **Active** service with this ID. It can be either a standalone Product (Package) or a Product Addon.
    - **How to Setup (Domain Specific)**: 
        1. Go to **Setup -> Products/Services -> Products/Services**.
        2. Create a new Product (Type: **Other**) called "Cloudflare Pro".
        3. Note the **ID** of this product and enter it in the Cloudflare Manager settings.
        4. Now, any client who buys this standalone product will have Pro features unlocked on all their domains.
    - **How to Setup (Hosting Addon)**: 
        1. Go to **Setup -> Products/Services -> Addons**.
        2. Create an addon called "Cloudflare Pro Upgrade".
        3. Note the **ID** and enter it in the Cloudflare Manager settings.
        4. This allows you to sell Cloudflare as an upgrade to existing hosting plans.

### B. DNS Template Manager (The "Core" Logic)
This table defines which records are created automatically when a domain is first added.
- **Type**: Choose A, CNAME, MX, or TXT.
- **Name**: Use `@` for the root domain or specify a subdomain (e.g., `www`).
- **Content**: Use dynamic variables `{ip}` and `{domain}`.
- **Proxied**: Toggle the Cloudflare Proxy (Cloud icon) on or off for that specific record.

### C. Domain Synchronization Tool
Located under the **Domain Sync Tool** tab.
- **Selective Sync**: Manually enable or disable Cloudflare management for existing domains.
- **Status Indicators**: Instantly see which domains are 'Enabled' and managed by the addon.
- **Bulk Control**: Ensures domains hosted elsewhere or specifically excluded by the admin remain untouched. Client-area management is hidden for 'Disabled' domains.

## 2. Client Area Features

### A. Cloudflare Center (Global Dashboard)
Located under **Services -> Cloudflare Center**.
- **Unified List**: Displays all active domains in the client's account.
- **Filter**: Use the search bar to find specific domains instantly.
- **Manage Button**: Quick access to the individual domain manager.

### B. Individual Domain Manager
Accessed via **Domain Manager -> example.com -> Cloudflare Manager**.
- **Managed Mode (Free)**: Standard for all active domains. Automatically provisions the zone using Admin templates.
- **Pro Tier Banner**: Appears for users on the free tier, encouraging them to upgrade to unlock advanced features.

#### Button Functions:
- **Purge Cache**: Immediately clears the Cloudflare cache for the entire zone.
- **Pause Cloudflare (Toggle)**: Temporarily stops all Cloudflare proxying, directing traffic straight to your origin server.
- **Add Record**: Simple form to add `A`, `CNAME`, `MX`, or `TXT` records.
- **Delete Record (Trash Icon)**: Removes the DNS record from Cloudflare permanently.
- **Under Attack Mode (Toggle)**: Enables high-level DDoS protection if the site is being targeted.
- **Development Mode (Toggle)**: bypasses the cache for 3 hours (Locked for Free users).

## 3. Handling Existing Cloudflare Domains

If a domain is already active in a client's personal Cloudflare account, the module will detect a conflict (Error 1061). The client has two paths:

1. **Migrate to Managed Tier**:
   - The client must delete the domain from their personal Cloudflare dashboard.
   - Once deleted, they can click **Manage** in WHMCS to instantly provision it on your Master account.
2. **Use BYOT (Pro Tier)**:
   - If the client has a Pro subscription, they can keep the domain in their own account and simply provide their **API Token** in the WHMCS manager. This avoids any downtime or migration steps.

## 4. Technical Notes
- **Provisioning**: Logic is triggered the first time a user visits the "Manage" page for an active domain.
- **Tier Sync**: The system checks in real-time if the user has the required addon ID to unlock "PRO" mode.
