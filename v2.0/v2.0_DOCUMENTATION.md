# Cloudflare WHMCS Module v2.2 - Operations Guide

Welcome to the comprehensive operations guide for the Cloudflare Premium DNS WHMCS Module. This document provides detailed instructions on how to use the module effectively, understand its core features, and manage your client's domains.

---

## 1. Architectural Deployment Modes

This module utilizes a **Strict Infrastructure-Based Management** coupled with **BYOT (Bring Your Own Token)**. The outdated concept of proxying everything through a single master account has been replaced to ensure better security, scalability, and performance.

### Infrastructure Clusters
**How it works:** The administrator defines Infrastructure Clusters (e.g., WHMCS servers or custom IP addresses). 
- **Benefits:** You can assign specific clusters to specific WHMCS products. When a client purchases a product, they get access to the DNS templates defined for that cluster.
- **Templates:** DNS records are generated dynamically using variables like `{domain}` and `{ip}`.

### BYOT - Bring Your Own Token
**How it works:** The client brings their own API token or Global Key generated from their personal Cloudflare account and inputs it into the WHMCS portal.
- **Benefits:** 100% administrative control remains with the client. They maintain their own isolated data privacy.
- **Security:** If one domain gets flagged by Cloudflare for abuse, no other clients are impacted.

## 2. Client Area Features & Navigation

The client interface provides a premium, "zoomed-out" modern experience.

### The Dashboard (Premium DNS)
Clients can access the main dashboard via the primary **Services** menu.
- **Overview:** Displays connected accounts and active assets.
- **Managed Accounts:** Clients can add their Cloudflare API credentials safely. The UI includes an interactive guide to assist with this.
- **Active Assets:** Displays domains currently routed through the connected accounts.
- **Sync Domains:** Lists all domains owned by the user (or all Cloudflare domains if the admin toggle is on) and allows them to initialize sync.

### Domain Management (`Manage` Interface)
Accessible via the "Manage Assets" button.
- **Asynchronous AJAX Core:** All functions (DNS additions, deletions, and cache purging) are fully asynchronous. Actions process in the background with immediate SweetAlert2 feedback, eliminating page reloads.
- **Functional DNS Table:** Real-time fetching of DNS records from Cloudflare. Users can instantly add or delete records directly from WHMCS.
- **Quick Actions:** 
  - **Purge All Cache:** Instantly clears the Cloudflare cache for the zone.
  - **Re-Sync Infrastructure:** Pushes the cluster's default DNS templates to the domain.
  - **Danger Zone:** Delete the asset completely from the Premium DNS network.

## 3. Global Admin Configurations

### Fetch All Cloudflare Domains Toggle
- **What it is:** A toggle in the WHMCS Addon settings.
- **Default (Off):** The module strictly filters the user's Cloudflare zones, displaying only the domains that the user explicitly has registered/active in their WHMCS account.
- **Enabled (On):** The system acts as a universal Cloudflare extension, fetching and allowing management for *all* domains found in the user's Cloudflare account, regardless of whether they exist in WHMCS.

### Mass Sync Infrastructure
- **What it is:** A tool in the Admin Cluster Management page.
- **Why use it:** If you migrate a server to a new IP or change your DNS templates, clicking this button will instantly force-update the DNS records for *all* client domains linked to that cluster.

## 4. Troubleshooting & Self-Healing

- **Database Errors:** The module includes an aggressive "Self-Healing" schema validation. If database columns are modified or dropped, navigating to the module will automatically reconstruct the schema without data loss.
- **API Errors / Blank Pages:** The module now gracefully handles Cloudflare API timeouts or permission errors using safe error catching, preventing WHMCS fatal crashes and alerting the user cleanly via JSON responses.
